# Prompt Log

## Задание 1: Определение агентов и их ролей

### Промпт 1
**Инструмент:** Sisyphus (Gemma 4 31B)
**Промпт:**
```
ЗАдание 1 Ты — системный архитектор в области IoT и мультиагентных систем. Моя предметная область — «Умный дом». Мне необходимо выполнить первое задание лабораторной работы: «Определение агентов и их ролей».

Напиши подробный отчет, структурированный в виде таблицы или списка, для 4 типов агентов:
1. Агент освещения
2. Агент климат-контроля
3. Агент безопасности
4. Агент энергоменеджмента

Для каждого агента ОБЯЗАТЕЛЬНО укажи следующие пункты:
- Роль агента: за что он отвечает в системе.
- Входные данные (Input): какие параметры он принимает в JSON-формате (например, команды от оркестратора или данные с датчиков).
- Выходные данные (Output): что он возвращает в качестве результата (статус выполнения, текущее состояние).
- Бизнес-правила: логика, по которой агент принимает решения (например, «если освещенность < 200 лк, включить свет»).

Стиль текста: технический, академический, подходящий для вставки в пояснительную записку к лабораторной работе. 
```

**Результат:** Сгенерирован подробный технический отчет с описанием четырех типов агентов (Освещение, Климат, Безопасность, Энергоменеджмент). Для каждого агента определены роль, формат входных/выходных JSON-данных и детальные бизнес-правила.
- Создан файл `agents_definition.md` с содержанием технического отчета.

### Итого
- **Количество промптов:** 1
- **Что пришлось исправлять вручную:** Скорректировал структуру JSON-сообщений для обеспечения единообразия между всеми типами агентов и уточнил формулировки бизнес-правил, чтобы они были однозначными для последующей реализации в коде.
- **Время:** ~5 мин

## Задание 2: Разработка прототипа агента на Go

### Промпт 1
**Инструмент:** Sisyphus $\to$ golang-pro (Gemma 4 31B)
**Промпт:**
```
Ты — senior Go разработчик с глубоким опытом в построении распределенных систем и работе с брокерами сообщений. Твоя задача — реализовать прототип одного из агентов для мультиагентной системы «Умный дом» на языке Go.

Выбранный агент: Агент освещения (Lighting Agent).

Технические требования:
1. Стек: 
   - Язык: Go (последняя стабильная версия).
   - Библиотека для NATS: github.com/nats-io/nats.go.
   - Формат обмена данными: JSON.
2. Функциональные требования:
   - Подписка: Агент должен подключаться к NATS серверу и подписываться на тему (subject) tasks.lighting.
   - Обработка данных: 
     - Принимать входящее сообщение в формате JSON (структура Task: ID, Type, Payload).
     - Десериализовать Payload в структуру параметров освещения (согласно определению в agents_definition.md).
   - Бизнес-логика: Реализовать простую логику обработки:
     - Если команда set_state и state == "ON", агент должен «включить» свет (имитация через лог).
     - Если в данных датчиков ambient_light < 200, агент должен автоматически сгенерировать команду на включение света, даже если явной команды не было.
   - Ответ: После обработки агент должен опубликовать результат в тему tasks.completed в формате JSON (структура Result: TaskID, Success, Output).
3. Требования к качеству кода:
   - Структура проекта: 
     - main.go — точка входа, инициализация NATS и запуск подписки.
     - internal/agent/ — логика обработки задач и бизнес-правила.
     - internal/models/ — структуры данных для JSON (Task, Result, LightingParams).
   - Логирование: Использовать стандартный пакет log или zap/logrus для вывода событий: «Получена задача ID», «Применение правила: освещенность низкая», «Результат отправлен».
   - Отказоустойчивость: Реализовать корректную обработку ошибок при подключении к NATS и десериализации JSON (чтобы агент не «падал» при получении некорректного сообщения).
   - Graceful Shutdown: Обработка сигналов ОС (SIGINT, SIGTERM) для корректного закрытия соединения с NATS.
4. Ожидаемый результат:
   - Полный исходный код проекта.
   - Файл go.mod с зависимостями.
   - Краткий README.md с инструкцией по запуску и примером JSON-сообщения для тестирования через nats pub.
Результат должен быть промышленного качества: с соблюдением идиоматики Go, четким разделением ответственности и полной готовностью к запуску.
```

**Результат:** Реализован полноценный агент освещения в директории `lighting-agent/`. 
- Создана правильная структура проекта (`internal/agent`, `internal/models`).
- Реализовано подключение к NATS с автоматическим переподключением.
- Внедрена бизнес-логика управления светом и авто-триггер при низком уровне освещенности (< 200 лк).
- Обеспечен корректный Graceful Shutdown через обработку системных сигналов.
- Создан `go.mod` и подробный `README.md` с примерами тестирования.

### Итого
- **Количество промптов:** 1
- **Что пришлось исправлять вручную:** Вручную создал структуру папок проекта (`internal/agent`, `internal/models`), настроил `go.mod` и проверил совместимость версий библиотеки `nats.go` с установленной версией Go.
- **Время:** ~3 мин

## Задание 3: Разработка оркестратора на Python

### Промпт 1
**Инструмент:** Sisyphus $\to$ python-pro (Gemma 4 31B)
**Промпт:**
```
ЗАДАЧА: Реализовать профессиональный Оркестратор агентов на Python для мультиагентной системы «Умный дом».

ОЖИДАЕМЫЙ РЕЗУЛЬТАТ:
Профессиональная реализация оркестратора в директории 'orchestrator/'.
Критерии успеха:
1. Структура проекта:
   - orchestrator/main.py (Точка входа, демонстрация отправки задач)
   - orchestrator/core.py (Класс AgentOrchestrator)
   - orchestrator/models.py (Pydantic-модели для Task и Result)
   - orchestrator/.env.example (Пример переменных окружения)

2. Основной функционал:
   - Использование 'nats-py' и 'asyncio'.
   - Реализация паттерна Request-Response поверх NATS:
     - Оркестратор публикует задачу в конкретную тему (например, 'tasks.lighting').
     - Он слушает тему 'tasks.completed' для получения результатов.
     - Использование внутреннего маппинга (например, Dict[str, asyncio.Future]) для корреляции 'task_id' в ответе с оригинальным запросом.
   - Метод `send_task`:
     - Сигнатура: `async def send_task(self, subject: str, payload: dict, task_type: str, timeout: float = 30.0) -> dict`
     - Должен генерировать уникальный `task_id` (UUID).
     - Должен обрабатывать `asyncio.TimeoutError` и очищать ожидающий Future.
   - Коллбэк `on_result`:
     - Корректный парсинг JSON-ответа и разрешение соответствующего Future.

3. Техническое совершенство:
   - Полная типизация (PEP 484).
   - Надежная обработка ошибок (сбои подключения, ошибки декодирования JSON).
   - Структурированное логирование (использование модуля 'logging').
   - Конфигурация через переменные окружения (NATS_URL).
   - Graceful shutdown (корректное закрытие) соединения NATS.

4. Интеграция:
   - Обеспечить полную совместимость JSON-структуры с Go-агентом освещения:
     - Task: { "id": str, "type": str, "payload": dict/raw_json, "timestamp": str }
     - Result: { "task_id": str, "success": bool, "data": any, "error": str, "timestamp": str }

ТРЕБУЕМЫЕ ИНСТРУМЕНТЫ:
- write (для создания файлов)

ОБЯЗАТЕЛЬНО:
- Использовать Pydantic для валидации данных.
- Гарантировать неблокирующую работу оркестратора.
- Предоставить понятный main.py, который отправляет несколько тестовых задач в тему 'tasks.lighting'.

ЗАПРЕЩЕНО:
- Использовать блокирующие вызовы (например, time.sleep) внутри async-функций.
- Хардкодить NATS URL.

КОНТЕКСТ:
В системе уже есть Go-агент освещения, который слушает 'tasks.lighting' и отвечает в 'tasks.completed'.
```

**Результат:** Реализован полноценный оркестратор в директории `orchestrator/`.
- Внедрена архитектура Request-Response через `asyncio.Future` и NATS.
- Реализована строгая валидация данных с помощью Pydantic.
- Создан `main.py` с четырьмя сценариями тестирования (включая авто-триггер и таймауты).
- Проведена интеграционная проверка: Оркестратор $\to$ Go-Агент $\to$ Оркестратор. Все сценарии пройдены успешно.

### Итого
- **Количество промптов:** 1
- **Что пришлось исправлять вручную:** 
  1. Исправил `AttributeError` в `core.py`, заменив доступ к внутреннему полю `_loop` на `asyncio.get_event_loop()`.
  2. Исправил `UnicodeEncodeError` в `main.py`, заменив символы-эмодзи на текстовые маркеры `[OK]`, `[ERROR]` для совместимости с консолью Windows.
- **Время:** ~15 мин
