# Определение агентов и их ролей в мультиагентной системе «Умный дом»

В рамках проектирования мультиагентной системы (МАС) «Умный дом» принята децентрализованная архитектура, в которой каждый агент представляет собой автономный программный модуль, инкапсулирующий специфическую бизнес-логику управления отдельным поддоменом инфраструктуры. Взаимодействие осуществляется через брокер сообщений NATS по модели «издатель-подписчик» (pub-sub) под управлением центрального оркестратора.

## Описание агентов

### 1. Агент освещения (Lighting Agent)
**Роль**: Управление световыми приборами, создание сценариев освещенности и оптимизация визуального комфорта в помещениях.

*   **Входные данные (Input)**:
    ```json
    {
      "command": "set_state", 
      "params": {
        "room_id": "living_room",
        "device_id": "light_01",
        "state": "ON",
        "brightness": 75, 
        "color_temp": 4000
      },
      "sensor_data": {
        "ambient_light": 150
      }
    }
    ```
*   **Выходные данные (Output)**:
    ```json
    {
      "status": "success",
      "current_state": {
        "device_id": "light_01",
        "state": "ON",
        "brightness": 75
      },
      "timestamp": "2026-05-13T10:00:00Z"
    }
    ```
*   **Бизнес-правила**:
    1. **Автоматическая коррекция**: Если `ambient_light` (освещенность) падает ниже 200 лк в присутствии пользователя, агент инициирует включение света.
    2. **Приоритет команд**: Прямая команда от оркестратора (пользователя) имеет высший приоритет над автоматическими правилами датчиков.
    3. **Энергосбережение**: В случае отсутствия движения в помещении более 10 минут, агент переводит освещение в состояние `OFF`.

### 2. Агент климат-контроля (Climate Control Agent)
**Роль**: Поддержание заданных параметров микроклимата (температура, влажность, чистота воздуха) и управление HVAC-системами.

*   **Входные данные (Input)**:
    ```json
    {
      "command": "update_target",
      "params": {
        "target_temp": 22.5,
        "target_humidity": 45,
        "mode": "AUTO"
      },
      "sensor_data": {
        "current_temp": 25.1,
        "current_humidity": 60,
        "co2_level": 800
      }
    }
    ```
*   **Выходные данные (Output)**:
    ```json
    {
      "status": "processing",
      "active_devices": ["AC_unit_01", "humidifier_01"],
      "estimated_time_to_target": 1200,
      "system_load": "medium"
    }
    ```
*   **Бизнес-правила**:
    1. **Гистерезис**: Для предотвращения частого включения/выключения оборудования используется температурный гистерезис $\pm 0.5^\circ\text{C}$.
    2. **Приоритет качества воздуха**: При превышении уровня $\text{CO}_2$ порога в 1000 ppm агент принудительно активирует систему вентиляции, независимо от текущих настроек температуры.
    3. **Безопасный режим**: При обнаружении критического перегрева оборудования агент переводит систему в режим `OFF` и отправляет сигнал тревоги оркестратору.

### 3. Агент безопасности (Security Agent)
**Роль**: Мониторинг периметра, контроль доступа в помещение и управление системами оповещения об угрозах.

*   **Входные данные (Input)**:
    ```json
    {
      "command": "set_arm_mode",
      "params": {
        "mode": "STAY", 
        "auth_token": "abc-123-xyz"
      },
      "sensor_data": {
        "door_sensor": "OPEN",
        "motion_detected": true,
        "camera_event": "unknown_person_detected"
      }
    }
    ```
*   **Выходные данные (Output)**:
    ```json
    {
      "status": "alert",
      "security_level": "CRITICAL",
      "event": "unauthorized_entry",
      "triggered_alarms": ["siren_01", "push_notification"]
    }
    ```
*   **Бизнес-правила**:
    1. **Логика тревоги**: Если режим системы установлен в `ARMED` (Охрана) и зафиксировано событие `door_sensor == "OPEN"`, агент немедленно активирует сигнал тревоги.
    2. **Верификация**: При попытке смены режима безопасности требуется валидный `auth_token`; при трех неудачных попытках агент блокирует доступ и уведомляет владельца.
    3. **Иерархия событий**: События от датчиков дыма и утечки газа имеют абсолютный приоритет над любыми другими командами и переводят систему в режим экстренной эвакуации.

### 4. Агент энергоменеджмента (Energy Management Agent)
**Роль**: Мониторинг энергопотребления, оптимизация нагрузки на электросеть и снижение эксплуатационных расходов.

*   **Входные данные (Input)**:
    ```json
    {
      "command": "optimize_load",
      "params": {
        "max_power_limit": 3500,
        "tariff_zone": "PEAK"
      },
      "sensor_data": {
        "total_consumption": 3800,
        "device_loads": {
          "electric_oven": 2000,
          "dishwasher": 1200,
          "ac_unit": 600
        }
      }
    }
    ```
*   **Выходные данные (Output)**:
    ```json
    {
      "status": "optimized",
      "actions_taken": [
        {"device": "dishwasher", "action": "pause", "reason": "peak_tariff"}
      ],
      "saved_energy": 1.2,
      "current_load": 2600
    }
    ```
*   **Бизнес-правила**:
    1. **Приоритезация нагрузки**: При превышении `max_power_limit` агент отключает устройства согласно иерархии приоритетов: *Вторичные (посудомойка) $\to$ Комфортные (кондиционер) $\to$ Критические (холодильник/безопасность)*.
    2. **Тарифная оптимизация**: В зоне действия «Пикового тарифа» (`PEAK`) агент ограничивает мощность энергозатратных приборов, если они не отмечены как приоритетные.
    3. **Прогнозирование**: Если текущий темп потребления приведет к превышению лимита в ближайшие 15 минут, агент отправляет рекомендацию оркестратору о необходимости перераспределения ресурсов.
